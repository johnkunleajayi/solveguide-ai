# SolveGuide AI

Understand the question. Find the answer. Learn why.

SolveGuide can currently **CAPTURE and UNDERSTAND a question** when its local
backend and vision provider are configured. It does **not** yet determine or
recommend the correct answer. Milestone 4 stops at a structured question observation.
Real-provider accuracy still requires a controlled live test with a configured key.

## Start development

Prerequisites: Windows 10 1903+ with supported Graphics Capture/D3D11 hardware,
WebView2, MSVC Build Tools, Node/npm and Python 3.12+. Python 3.14 was used here.
Run all commands from `D:\solveguide-ai`:

```powershell
npm.cmd install --cache .cache/npm
npm.cmd run setup:backend
if (-not (Test-Path backend/.env)) { Copy-Item backend/.env.example backend/.env }
```

Edit `backend/.env` locally and set your own `OPENAI_API_KEY`. Never put it in chat,
a `VITE_*` variable, React, Rust or `.env.example`. Restart the backend after edits.
No key is supplied or generated by SolveGuide. A missing key leaves health available
and returns a clear `provider_not_configured` error for Read Question.

Start the backend in one terminal:

```powershell
npm.cmd run backend
```

Start the native app in another:

```powershell
npm.cmd run desktop
```

The backend binds only `127.0.0.1:8000`; health is `http://127.0.0.1:8000/api/health`.
Frontend-only development: `npm.cmd run dev` at `http://127.0.0.1:1420`.
Native capture requires the actual Tauri application. No installer or Python
sidecar bundling is configured, so the backend is currently a separately run process.

## Architecture: a modular monolith

```text
Windows Graphics Capture / Direct3D11
  -> Rust capture module -> typed CaptureResult -> React capture preview
  -> explicit Read Question -> local FastAPI -> VisionService
  -> VisionProvider -> OpenAIVisionProvider -> QuestionObservation -> desktop UI
```

- `src/App.tsx`: shell, modal visibility, theme and pointer preferences.
- `src/capture/`: existing native capture contract, adapter and state machine.
- `src/vision/`: observation types/runtime guard, HTTP client and cancellable state.
- `CaptureDialog.tsx`, `CapturePreview.tsx`: selection, preview and explicit reading action.
- `QuestionObservationView.tsx`: prompt, instructions, options, context, visuals and warnings.
- `src/styles/`: Neutral Light tokens and focused, reusable presentation styles.
- `src-tauri/src/capture/`: Windows discovery, validation and single-frame capture.
- `backend/app/config.py`: backend-only pydantic-settings configuration.
- `backend/app/schemas.py`: strict request and observation models.
- `backend/app/images.py`: bounded in-memory PNG decoding/validation.
- `backend/app/providers/base.py`: `VisionProvider` protocol, with one `observe` operation.
- `backend/app/providers/openai.py`: official async OpenAI SDK Responses API adapter.
- `backend/app/service.py`: provider-independent orchestration and output revalidation.
- `backend/app/api.py`, `middleware.py`, `main.py`: routes, request bounds, origins,
  dependency injection, safe error envelopes and application factory.

The provider contract supports future local/multimodal alternatives without coupling
routes or React to OpenAI. Only OpenAI is implemented. No database, microservice,
OCR engine, retrieval, authentication, answer generation or reasoning stage exists.

## Capture and Read Question

Analyze Question opens capture preparation. Screen and Window require an explicit
source choice. Region is a typed, visibly unavailable option; no region capture
is implemented. Monitor inventory includes dimensions, desktop position and primary
status. Windows are filtered for visibility/minimization/cloaking/tool/untitled/system
and SolveGuide-owned windows. Native opaque tokens are revalidated before capture.
No frontend-supplied paths or HWNDs are accepted. An unchanged source retains its
token across source refresh so cancellation does not break Retake.

Capture acquires one frame off the UI thread, with a five-second frame wait and
40-megapixel bound. SolveGuide hides briefly for monitor capture and restores on
success/failure. Windows are captured as window surfaces, never via a fallback crop
of overlapping desktop content. The OS capture indicator is retained. Preview
reports actual content dimensions, which can differ from discovery bounds due to
invisible Windows borders. Retake, Change Source and Clear capture remain available.

Capture itself uploads nothing. The separate **Read Question** action explicitly
sends the current PNG to the local backend and then OpenAI. The UI states this before
the action. Reading has progress, Cancel and explicit Retry states. Retake/Clear
invalidate observation state and abort the client request; late replies are ignored.
Cancellation cannot guarantee that a provider request already accepted by OpenAI
will stop or avoid charges. No automatic retry or background reading occurs.

## API and QuestionObservation

`POST /api/v1/vision/question` accepts JSON with only:

```json
{ "media_type": "image/png", "image_base64": "<base64 PNG bytes>" }
```

No paths, remote URLs, source/window titles or filesystem references are accepted.
The streaming JSON body is capped at 14 MiB before parsing; decoded PNG at 10 MiB
and 40 megapixels. MIME type, base64, PNG structure, frame count and actual decoder
are checked. Only one vision request runs at a time; parallel work returns busy.
Malformed input is rejected without echoing sensitive validation input.

A strict `QuestionObservation` contains:

| Field | Meaning |
| --- | --- |
| status | detected, unclear or no_question |
| question_type | multiple_choice, multiple_select, true_false, short_answer, essay, mathematics, code, mixed or unknown |
| question_text | Complete visible prompt or nullable partial/absent text |
| options | Visible label/text pairs, with no correctness/recommendation field |
| instructions | Relevant visible task instructions |
| required_selection_count | Explicit count when established by the image; otherwise null |
| visible_context | Supporting question content, excluding unrelated application chrome |
| visual_elements | Typed chart/diagram/table/screenshot/illustration/formula/code/other descriptions, optional visible text and code language |
| extraction_confidence | Bounded reading-quality estimate; not calibrated certainty or answer confidence |
| warnings | Uncertainty, cropped/obscured content or incomplete extraction |

The adapter uses `responses.parse(..., text_format=QuestionObservation)` and validates
the parsed result again. It handles refusal, incomplete/malformed output, auth,
quota/rate limits, connectivity and timeout errors. Screenshot instructions are
untrusted data, not instructions to the provider. Math notation and code indentation
are preserved where legible. No question is forced into MCQ and missing text is not
invented. The schema rejects extra fields, including answer/reasoning fields.

Errors use `{ "error": { "code": "...", "message": "..." } }` with safe messages.
`GET /api/health` reports process availability and provider configuration presence,
never credentials. Successful no-question/unclear results are observations with
review guidance, not fabricated successes or answers.

## Configuration and local security

| Backend variable | Default |
| --- | --- |
| OPENAI_API_KEY | Empty/missing; reading fails gracefully |
| OPENAI_VISION_MODEL | gpt-4.1-mini |
| VISION_TIMEOUT_SECONDS | 45 seconds, configurable from 1 to 90 |
| VISION_MAX_OUTPUT_TOKENS | 4096, bounded from 512 to 8192 |

GPT-4.1 mini is a configurable non-reasoning default supporting image inputs and
structured output; the model name lives only in backend configuration. The official
SDK is pinned in the lock file. It receives the key from a masked SecretStr backend
setting and uses the explicit OpenAI API endpoint. SDK retries are disabled. A provider
wall-clock deadline and explicit connection/network timeouts bound requests; the
frontend also has a 110-second network limit and a visible manual Retry action.

Development CORS allows only `http://127.0.0.1:1420` and the Windows Tauri origin
`http://tauri.localhost`, without credentials or wildcard origins. Vision POSTs also
require a matching Origin; CORS alone is not authentication. Trusted hosts are
loopback names. The frontend endpoint is centralized in `src/vision/client.ts`.
Tauri CSP adds only `http://127.0.0.1:8000` to connect-src; no new native permissions
or direct frontend-to-OpenAI connection is added. Vite watcher exclusions remain
unchanged for `src-tauri`, `.tools` and `.cache`.

This is a local development backend, not a public production deployment. Do not
bind it to a public interface. A future hosted deployment needs explicit HTTPS,
origin/endpoint configuration and separate access/abuse controls; none are silently
substituted by this milestone. Host/origin checks do not block arbitrary local code.

## Privacy and image lifecycle

Capture -> process-memory preview -> explicit Read Question -> bounded in-memory
backend validation -> configured OpenAI provider -> structured observation -> UI.
The backend never saves the image, creates history, uploads a Files API object,
logs base64/text/observations or stores data in a database. Request image buffers
become unreachable after completion. Logs contain only allowlisted event metadata
(request ID, outcome code and duration); SDK/HTTP debug logging is suppressed.
Response caching is disabled. Only appearance and Pointer Light preferences persist.
Clear/reload/exit release current UI capture/observation references. There is no
secure-memory-wipe promise; normal OS pagefile/crash policies remain external.

OpenAI receives the image only on Read Question. `store=False` disables response
application storage; it is not a promise of zero provider retention. The account's
OpenAI data controls and provider policies still apply. Keep sensitive material out
of controlled tests. Never enable raw request tracing or SDK debug payload logging.

## Visual/accessibility foundation

Preserve the black-and-white Neutral Light identity: near-black/charcoal signature
dark mode, independently designed off-white/ink light mode, persisted System mode.
Tokens own colors, type, spacing, borders, focus, shadows and restrained luminous
motion. System fonts and browser-only primitives remain reusable for a future web app.

Pointer Light uses DOM refs/transforms and a bounded rAF loop, never React state
per pointer move. It requires fine hover, preference on, no reduced motion and no
forced colors. Native cursors, text selection, coarse/touch/keyboard behavior and
modal suspension remain. Reduced motion disables ambient/reveal/sweep transitions.
Semantic controls, visible focus, live reading/error states and natural vertical
scrolling preserve desktop usability. External model text is escaped React text,
not HTML; code/math preserve whitespace. No correct-option styling is present.

## Current limitations and future architecture

Physical multi-monitor/mixed-DPI/rotation/HDR compatibility requires broader hardware
testing. Native discovery uses a temporary per-thread per-monitor-v2 DPI context,
including negative origins. Protected/elevated/special/minimized windows may fail
or appear blank. SDR capture has no HDR tone mapping. Region selection remains
unimplemented and must not be faked. This milestone does not change native capture.
Vision may misread text, symbols, layout or selection counts: review warnings and the
original image. General reasoning and answer generation remain outside the pipeline.

### Reusable Context Library and Session Preparation (not implemented)

Future PDF, DOCX, TXT, pasted notes and supported materials belong to a reusable
library across sessions; users must not repeatedly upload the same material. A
session may identify the work, select/review library material references, choose
a reasoning mode and begin. Selected materials guide reasoning without becoming
the exclusive source unless explicitly requested.

| Future mode | Contract |
| --- | --- |
| GENERAL | Normal model knowledge and reasoning |
| CONTEXT GUIDED | Selected materials guide reasoning while broader knowledge stays available; default when materials are selected |
| MATERIALS ONLY | Answer only with sufficient selected-material support and communicate insufficiency |

No uploads, parsing, retrieval, RAG, embeddings, vector storage or session workflow
is implemented. Future user-selected region capture belongs in Tauri/Rust. Ordinary
screen-sharing privacy may later use supported native OS capture exclusion, never
CSS tricks or anti-proctoring, monitoring/detection evasion or security circumvention.
No capture exclusion is implemented. The eventual web experience may reuse visual
tokens, observation presentation and browser interaction primitives; no separate
web application is created here.
